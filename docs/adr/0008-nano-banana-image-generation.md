# ADR 0008: Image generation with Google Nano Banana through OpenRouter

Status: accepted, 2026-11-19.

## Context
M3 needs post images in the brand's style that show the owner's real products. ARCHITECTURE.md asks for an `ImagePort` and a Phase 0 benchmark (Hindi text, product fidelity) before a provider is picked. The owner chose Google's Nano Banana family without a formal benchmark, through the gateway already in use (ADR 0004), with two or three models as fallbacks. Credits and pricing (M13) are not built yet, and the Brain's tracking of generated content (BUSINESS_BRAIN.md phase 3) comes after this flow works.

## Decision
- **Provider.** `ImagePort` in `infra/llm-providers`, implemented by `OpenRouterImageAdapter` on OpenRouter's Image API (`POST /images`, `response_format: b64_json`, `resolution: 1K`, one image per call). Same key, base URL, error mapping and privacy routing as text: strict mode sends `provider.zdr: true` and `data_collection: "deny"`. On 2026-11-19 every model below had a zero-data-retention endpoint on Google Vertex.
- **Models are configuration.** `OPENROUTER_MODEL_IMAGE` is an ordered list, default `google/gemini-nano-banana-2.1` (newest), then `google/gemini-3.1-flash-image` (Nano Banana 2), then `google/gemini-3-pro-image` (Nano Banana Pro, the most expensive). The `image.generate` task tries them in order. It moves on for failures another model may not share (no provider, upstream error, rate limit, timeout, no image returned) and stops for failures every model would share (auth, gateway account out of credit, cancelled).
- **Prompt.** Composed deterministically in `modules/ai` (`image.generate@2`) from the owner's brief, the format, confirmed visual facts, colours and content themes from the Business Brain (`MemoryService.visualContext`), up to 3 photos of the chosen product (to keep it faithful) and up to 2 of the owner's recent posts (for look only). There is no separate LLM step: the image models reason over the prompt themselves.
- **Design styles (2026-11-19, owner-approved).** A profile field, "Post design style" (`postDesignStyle`, default `designed`), sets how much design goes on the picture, and each image can override it. `designed` asks for an agency-style promotional post: a headline, subheading and button printed verbatim, the logo, and themed details. `minimal` is a headline and subheading over a clean picture. `photo` allows at most a headline. If the brand has a logo it is sent as a reference image with a copy-exactly instruction. It is on by default except for `photo`, with a switch per image. A designed post without a headline gets a short one written by the model, with no prices, offers or health claims. Version 1 printed only one line and never used the logo; jobs created before this are shown as photo-first.
- **Storage.** Generated bytes are uploaded server-side to Cloudinary under `marketpilot_generated/<workspaceId>` with the same signed upload as ADR 0006 (no SDK). Only the delivery URL is stored.
- **Jobs.** `studio_generation` (one owner request, generic `kind` so video can reuse it) and `studio_output` (one file each, with the model that made it and its cost). Both have RLS. The job runs in the API process, as the website scan does, and a job still open after 10 minutes is closed as lost. Moving it to the BullMQ `generation` queue is a worker change only.
- **Idempotency.** `POST /v1/studio/images` requires an `Idempotency-Key` (unique per workspace). A repeated key returns the first job and never pays twice.
- **Spend guard until credits exist.** At most 2 jobs running per workspace and `STUDIO_DAILY_IMAGE_LIMIT` images (default 40) per rolling 24 hours. Gateway cost is recorded per output and per job, so credits can be priced from real numbers.

## Consequences
- No Phase 0 benchmark was run. Hindi and Devanagari headline accuracy and product fidelity should be checked on real brands before launch; changing the order or the models is configuration only.
- Google (via Vertex) and Cloudinary are subprocessors for generated media. Product photos and past posts are sent to the model as public URLs.
- Delivery URLs are public, so generated drafts must not contain anything private.
- Credits (CLAUDE.md rule 9) are deliberately not enforced yet. When M13 lands, reservation replaces the daily cap and settlement uses the recorded cost.
- Recording which outputs the owner approves or edits (L3 episodic memory) is deferred. The stored prompt, prompt version and outputs are enough to backfill it.
